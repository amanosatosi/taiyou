# T026 — Common SSA and explicit decoding support

Status: planned. Suggested owner: **Sol 6.1**. Scope: one focused implementation session unless explicitly bounded as research; split with coordinator approval if unexpected work appears.

## Objective

Normalize common SSA v4 records and approved legacy encodings into the same Track types.

## Prerequisites

[R001](R001.md), [T006](T006.md), [T008](T008.md). These must meet their acceptance gates before dependent work starts.

## Files and modules

Extend planned ass/{decode,styles,events}.rs; add attachments.rs only for approved bounded font payloads and tests/ssa.rs. All creation paths in this section are planned; inspect for intervening implementations before editing.

## Technical contract

R001 supplies SSA alignment/style/Marked/default mapping and accepted codepages. Host selects encoding; UTF-8 remains default. Distinguish file byte encoding from Style Encoding/font charset policy. If embedded fonts are enabled, decode within byte limits into host catalog input without filesystem extraction; preserve source/provenance.

## Expected behavior

Equivalent SSA/ASS fixtures lower to equivalent canonical fields; legacy bytes decoded with explicit codepage, not OS locale; invalid attachment fails with diagnostic/limit error; Marked is not mistaken for ASS Layer.

## Implementation guidance

Do not build a new legacy text codec; use reviewed dependency only if T002 process approves it. Font attachment syntax requires R001 evidence before enablement.

Read [CONTRACTS](../CONTRACTS.md#c2-input-and-immutable-ir). Read [COMPATIBILITY](../COMPATIBILITY.md#b2-documented-disagreements).

## Acceptance criteria

Declared common SSA and selected encoding fixtures pass; unsupported fields/forms stay visible. No accidental alteration of UTF-8 ASS behavior.

## Verification

Create SSA mapping/charset/decoding distinction and malformed attachment tests; run parser suite and focused cross-profile comparisons. Commands referring to Cargo/xtask are established by the task that creates that tooling; do not report them run before it exists.

## Forbidden changes

No locale guessing, automatic disk extraction, unrelated legacy formats, unknown codepage replacement without diagnostics or profile-default drift. Ordinary implementation cannot modify protected expected assets, tolerances or support classifications.

## Completion report

Report T026, integration base and commit IDs (or explicitly no Git), changed files, exact commands and pass/fail results, fixture/profile/source revisions, unsupported cases, limitations and follow-up IDs. Attach stage/image/report evidence required above. For measured changes provide raw before/after samples and environment; otherwise state no performance claim. Record any acceptance gate still open; do not mark the task complete when required evidence is missing.
