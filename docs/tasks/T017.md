# T017 — xy wrapping and deterministic collision

Status: planned. Suggested owner: **Sol 6.1**. Scope: one focused implementation session unless explicitly bounded as research; split with coordinator approval if unexpected work appears.

## Objective

Add automatic wrapping and pure collision placement for approved profiles.

## Prerequisites

[T010](T010.md), [T016](T016.md).

## Files and modules

Extend planned render/layout.rs; create collision.rs and tests/wrapping_collision.rs. All creation paths in this section are planned; inspect for intervening implementations before editing.

## Technical contract

Implement pinterf wrap0/1/2/3 semantics and C4 collision, keeping the separate `\\warpmode1` Unicode extension isolated. Keep line break choice, local metrics, placement and composition ordering separate. Re-shape line boundaries when context requires, via font API. Collision input includes entire active eligible set and border-inflated boxes.

## Expected behavior

Touching boxes do not collide in Core; bottom-aligned equal-layer events stack upward in canonical order; explicit pos is excluded; seek to same time gives same placement. Same width with different border may move a neighbor without changing its shape.

## Implementation guidance

Do not infer a smart-wrap heuristic. Read pinterf `GetWrapWidth`, `GetNextLine`, `MakeLines` and related parsing directly, then encode focused executable examples.

Read [CONTRACTS](../CONTRACTS.md#c4-font-resolution-shaping-and-layout). Read [CACHING](../CACHING.md#k2-exact-key-dependencies).
