# T020 — Move, fades and numeric transforms

Status: planned. Suggested owner: **Sol 6.1**. Scope: one focused implementation session unless explicitly bounded as research; split with coordinator approval if unexpected work appears.

## Objective

Evaluate time-varying placement, opacity and approved numeric tag transforms from absolute time.

## Prerequisites

[T019](T019.md), [R001](R001.md). These must meet their acceptance gates before dependent work starts.

## Files and modules

Extend planned ass/overrides.rs, render/evaluate.rs and tests/animation.rs. All creation paths in this section are planned; inspect for intervening implementations before editing.

## Technical contract

C1/C3 time units, ordered transform capture/interpolation, acceleration and boundary rules. Add move/fad/fade/t only for explicitly enumerated animatable properties; R001 gives legacy precedence. Dirty hints do not override keys.

## Expected behavior

Move midpoint is geometric midpoint for linear interval; before/after clamps; fade opacity at defined boundaries is exact; repeated/backward time yields same state; color-only t changes do not rebuild outlines. Zero-duration transition uses documented Core step rule.

## Implementation guidance

Use state-level numeric tests first, then image sequences. Do not accumulate deltas or quantize time to frame rate.

Read [CONTRACTS](../CONTRACTS.md#c3-evaluation-and-dependency-classification). Read [CACHING](../CACHING.md#k3-change-matrix).

## Acceptance criteria

Boundary/overlap/reset/invalid parameter tests pass; cached animation matches uncached for random timestamp order.

## Verification

Create animation_times, transform_order, fade_channels and animation_cache tests; run focused references and cargo test -p taiyou-render animation. Commands referring to Cargo/xtask are established by the task that creates that tooling; do not report them run before it exists.

## Forbidden changes

No new easing DSL, time-keyed every-stage cache, unsupported vector-clip morphing or guessed legacy behavior. Ordinary implementation cannot modify protected expected assets, tolerances or support classifications.

Attach stage/image/report evidence required above. For measured changes provide raw before/after samples and environment; otherwise state no performance claim. Record any acceptance gate still open; do not mark the task complete when required evidence is missing.
