# T019 — Typed caches and accountable memory

Status: planned. Suggested owner: **Sol 6.1; architect key review**. Scope: one focused implementation session unless explicitly bounded as research; split with coordinator approval if unexpected work appears.

## Objective

Add bounded retention to already-correct single-worker stages and prove invalidation.

## Prerequisites

[T017](T017.md), [T018](T018.md). These must meet their acceptance gates before dependent work starts.

## Files and modules

Create planned crates/taiyou-render/src/cache/{mod,keys,budget,store}.rs and tests/cache.rs; instrument stage constructors. All creation paths in this section are planned; inspect for intervening implementations before editing.

## Technical contract

K1–K4 full keys, unique allocation charges, typed stores, deterministic barrier eviction, bypass mode, per-frame dedup and statistics. Frame output leases survive renderer destruction. No disk/global cache. Shape key conservatively includes size.

## Expected behavior

Changing c reuses geometry/masks when partition unchanged; integer pos reuses local masks; fractional pos rebuilds raster; blur changes reuse fill; old frame stays readable after eviction/destruction. Tiny cache and no cache give same output/diagnostics.

## Implementation guidance

Implement coordinator dedup even with retention disabled. Keep cache APIs free of recursive stage execution; use full-key equality under injected hash collisions.

Read [CACHING](../CACHING.md#k1-ownership-and-policy). Read [CACHING](../CACHING.md#k3-change-matrix).

## Acceptance criteria

Every K3 row has a mutation test comparing fresh renderer; memory counters release on final owner, total retained cap respected, oversized entries bypass retention.
