# T006 — Bounded override tokenization

Status: planned. Suggested owner: **Luna 6**. Scope: one focused implementation session unless explicitly bounded as research; split with coordinator approval if unexpected work appears.

## Objective

Tokenize text, braces, escapes and the static Core override subset into ordered TextOps.

## Prerequisites

[T004](T004.md). These must meet their acceptance gates before dependent work starts.

## Files and modules

Create planned crates/taiyou-ass/src/overrides.rs and tests/overrides.rs; modify event text lowering only. All creation paths in this section are planned; inspect for intervening implementations before editing.

## Technical contract

Recognize N/n/h escapes and fn/fs/b/i/fscx/fscy/fsp/c/1c..4c/alpha/1a..4a/an/pos/r tags with typed parameters. Preserve unknown operation name/span. C2 limits apply; tokenizer always advances. Drawing and animated ops stay Unsupported until assigned tasks.

## Expected behavior

'{\\c&H0000FF&}A{\\r}B' yields ordered color/text/reset/text; commas inside pos stay parameter delimiters; literal text outside braces retains whitespace. Unterminated Core brace consumes remaining override block with a diagnostic, not a hang; document this Core recovery test.

## Implementation guidance

C2/C3. Do not silently use a recursive balanced-parenthesis parser for legacy compatibility; R001 owns that policy.

Read [CONTRACTS](../CONTRACTS.md#c2-input-and-immutable-ir). Read [CONTRACTS](../CONTRACTS.md#c3-evaluation-and-dependency-classification).
