# R002 — Choose compatible coverage, stroke and blur policies

Status: planned. Suggested owner: **Astra; Sol experiment assistance**. Scope: one focused implementation session unless explicitly bounded as research; split with coordinator approval if unexpected work appears.

## Objective

Test whether the FreeType baseline can satisfy the declared xy subset and specify any required replacement algorithm.

## Prerequisites

[R001](R001.md), [T012](T012.md). These must meet their acceptance gates before dependent work starts.

## Files and modules

Create planned docs/research/R002-coverage.md and experimental code under experiments/coverage/; proposed fixtures under validation/proposals/R002/. All creation paths in this section are planned; inspect for intervening implementations before editing.

## Technical contract

Compare pinned xy fill/widening/group overlap/blur/be/shadow alpha behavior against baseline using synthetic rectangles, acute corners, curves, self-intersections, anisotropic/zero-axis widths, fractional phases, translucent overlaps and rotated text. Measure coverage differences and construction cost, with separate source/capture evidence. No copying Rasterizer.cpp.

## Expected behavior

Report whether borders stay device-width under rotation/scale, which passes blur affects, kernel support/rounding, union and alpha rules. A failed parity case either gets a concrete algorithm specification and fixtures or remains unsupported; it is not waived by a global tolerance.

## Implementation guidance

Read the [local pinterf source files](../LOCAL_REFERENCES.md#main-xy-reference-pinterf-only) first; do not re-download them. Record file fingerprints and resolve archive/pin identity before certifying an oracle build.

Maximum two experiment sessions, compare FreeType stroke/raster versus an independently described scanline-widening candidate only if needed. Architect decides per family; if no acceptable candidate, issue a narrow follow-up rather than let T016 guess. Specify exact legacy numeric policy in reviewed contract appendix before dependent work.

Read [CONTRACTS](../CONTRACTS.md#c5-geometry-stroke-raster-and-effects). Read [decisions/002-font-and-raster](../decisions/002-font-and-raster.md).

## Acceptance criteria

Decision names backend, stroke space/grouping, exact kernel/rounding rules and accepted fixture set with performance evidence. Core baseline remains available. Unresolved families remain explicitly gated.

## Verification

**Execution:** Run compiler/Cargo/native builds and test executables in GitHub Actions, never on the user's PC. Only lightweight documentation/hash checks may run locally. Follow the [CI-first policy](../DEVELOPMENT.md#d0-execution-location-and-local-storage) and report candidate SHA plus Actions run/job links; unrun checks remain pending.

Use T015 comparator and microbench harness; publish raw A8 masks, expected/actual/diff and counters. Re-run selected experiment outputs twice for determinism. Commands referring to Cargo/xtask are established by the task that creates that tooling; do not report them run before it exists.

## Forbidden changes

No renderer-wide rewrite, translated GPL code, unreviewed tolerances, guessed legacy Gaussian sigma mapping or enabling incomplete families. Ordinary implementation cannot modify protected expected assets, tolerances or support classifications.

Attach stage/image/report evidence required above. For measured changes provide raw before/after samples and environment; otherwise state no performance claim. Record any acceptance gate still open; do not mark the task complete when required evidence is missing.
