# T031 — Extension lowering research after the usable release

Status: planned. Suggested owner: **Astra planning; Sol isolated experiments**. Scope: one focused implementation session unless explicitly bounded as research; split with coordinator approval if unexpected work appears.

## Objective

Translate concrete Mangetsu/libassmod requirements into small post-release tasks.

## Prerequisites

[T030](T030.md). These must meet their acceptance gates before dependent work starts.

## Files and modules

Create planned docs/research/T031-extensions.md and proposed ADRs/fixtures; no production extension implementation. All creation paths in this section are planned; inspect for intervening implementations before editing.

## Technical contract

Start with the supplied [local mangetsu tree](../LOCAL_REFERENCES.md#mangetsu-folder--libassmod), whose README identifies libassmod. Study its gradient/alpha, directional blur, movement/distortion and host images locally; record fingerprints rather than assuming equivalence to the earlier upstream pin. Do not treat the folder name as a complete authoritative Mangetsu specification. Map gradients→paint, ruby→layout groups, curves→placement, multi-border→coverage passes, distortion→geometry. .asa syntax remains blocked without a spec.

## Expected behavior

A gradient-only animation prototype reuses masks; multi-border creates ordered independent passes; image fill requires host resource input without filesystem tag loading. Unsupported advanced blend modes need explicit isolation semantics.

## Implementation guidance

Bound research to two sessions and one minimal gradient lowering experiment. Preserve fundamental contracts; propose only changes demanded by real examples.

Read [ARCHITECTURE](../ARCHITECTURE.md#a6-extension-seams). Read [SOURCES](../SOURCES.md#s3-still-to-inspect).

## Acceptance criteria

Each selected feature has authority, units, stage mapping, cache dependencies, license analysis and a small implementation task; unknown features remain deferred, not speculative APIs.

## Verification

Review proposed task contracts against existing pipeline; demonstrate experimental mask reuse with counters and deterministic pixels without shipping extension support. Commands referring to Cargo/xtask are established by the task that creates that tooling; do not report them run before it exists.

## Forbidden changes

No full extension suite, generic plugin/DSL framework, .asa invention, runtime file/network loading or changing ASS defaults. Ordinary implementation cannot modify protected expected assets, tolerances or support classifications.

## Completion report

Report T031, integration base and commit IDs (or explicitly no Git), changed files, exact commands and pass/fail results, fixture/profile/source revisions, unsupported cases, limitations and follow-up IDs. Attach stage/image/report evidence required above. For measured changes provide raw before/after samples and environment; otherwise state no performance claim. Record any acceptance gate still open; do not mark the task complete when required evidence is missing.
