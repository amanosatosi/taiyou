# T024 — Bounded parallel preparation and unique-key jobs

Status: planned. Suggested owner: **Sol 6.1; Astra concurrency review**. Scope: one focused implementation session unless explicitly bounded as research; split with coordinator approval if unexpected work appears.

## Objective

Parallelize independent preparation/mask/effect jobs with one renderer-owned pool.

## Prerequisites

[R003](R003.md), [T027](T027.md). These must meet their acceptance gates before dependent work starts.

## Files and modules

Create planned render/scheduler.rs; extend renderer/cache/font context lifecycle and tests/parallel_prepare.rs. All creation paths in this section are planned; inspect for intervening implementations before editing.

## Technical contract

C8/A5/K4: workers1 inline, N pool workers otherwise, caller coordinates, stable result slots, stage barriers, unique-key producers, no recursive miss waits, worker-local native/scratch contexts and stable resource preflight. R003 supplies deterministic batching thresholds.

## Expected behavior

Hundreds of identical masks build once per frame even with cache off; producer error propagates deterministically; workers>jobs succeeds; serial collision sees stable inputs; same request's budget result is independent of workers.

## Implementation guidance

Introduce Rayon via reviewed dependency record. Keep composition sequential in this task to isolate preparation failures.

Read [ARCHITECTURE](../ARCHITECTURE.md#a5-execution-and-determinism). Read [CACHING](../CACHING.md#k4-concurrent-protocol).

## Acceptance criteria

V6 bytes/diagnostics equal at1/2/4/8 workers, no deadlock or oversubscription, native handles stay on owning threads. Controlled benchmark reports absolute cost/scaling.

## Verification

Run20 seeded scheduling repetitions, cache/budget/failure stress, sanitizer/race tools where supported and R003 workload comparisons. Report unsupported instrumentation honestly. Commands referring to Cargo/xtask are established by the task that creates that tooling; do not report them run before it exists.

## Forbidden changes

No global pool, nested native threading, parallel collision, cache locks around native calls or new rounding behavior. Ordinary implementation cannot modify protected expected assets, tolerances or support classifications.
