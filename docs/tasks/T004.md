# T004 — Minimal ASS sections, styles and event records

Status: planned. Suggested owner: **Luna 6**. Scope: one focused implementation session unless explicitly bounded as research; split with coordinator approval if unexpected work appears.

## Objective

Parse UTF-8 ASS v4+ records into immutable IR with literal event text.

## Prerequisites

[T003](T003.md). These must meet their acceptance gates before dependent work starts.

[ADR-008](../decisions/008-track-ingestion-identity.md) and the integrated T003 interface were explicitly accepted by the repository owner for this parser baseline. Documentation CI and owner acceptance are not independent-review or T005 protection evidence.

## Files and modules

Create planned crates/taiyou-ass/src/{decode,sections,styles,events}.rs and tests/records.rs; modify ass lib.rs. All creation paths in this section are planned; inspect for intervening implementations before editing.

## Technical contract

Implement C2 Core parsing, Format mapping, defaults, source ordinals and bounded diagnostics. Until T006, preserve event text as one literal TextOp. Parse structural commas without splitting Text; styles resolve after all definitions. Unsupported text-not-last layout diagnoses. Use checked time/number parsing and input/event/text limits.

## Expected behavior

BOM and CRLF accepted; Dialogue text 'hello, world' retains comma; duplicate style name uses last definition with diagnostic; missing Default synthesizes it; invalid UTF-8 fails; end<=start remains inactive with diagnostic.

## Implementation guidance

C2. Keep ASS record parsing independent from override syntax. Use small synthetic fixtures with one difference each.

Read [CONTRACTS](../CONTRACTS.md#c2-input-and-immutable-ir). Read [TESTING](../TESTING.md#v7-safety-fonts-and-malformed-input).

## Acceptance criteria

Exact event fields/source spans/defaults and malformed-record recovery are tested; source order remains stable even when timestamps/layers differ.

## Verification

**Execution:** Run compiler/Cargo/native builds and test executables in GitHub Actions, never on the user's PC. Only lightweight documentation/hash checks may run locally. Follow the [CI-first policy](../DEVELOPMENT.md#d0-execution-location-and-local-storage) and report candidate SHA plus Actions run/job links; unrun checks remain pending.

Create tests for reordered Format fields, missing fields, commas, unknown sections, bad times, limit overflow and duplicate styles. Run cargo test -p taiyou-ass. Commands referring to Cargo/xtask are established by the task that creates that tooling; do not report them run before it exists.

## Forbidden changes

No legacy decoding, override evaluation, font loading, renderer behavior or source-policy changes. Ordinary implementation cannot modify protected expected assets, tolerances or support classifications.
