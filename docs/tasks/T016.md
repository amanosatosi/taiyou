# T016 — Borders and shadows for the approved subset

Status: planned. Suggested owner: **Sol 6.1**. Scope: one focused implementation session unless explicitly bounded as research; split with coordinator approval if unexpected work appears.

## Objective

Render static borders and shadows with correct grouping and ordered passes.

## Prerequisites

[R002](R002.md), [T014](T014.md). These must meet their acceptance gates before dependent work starts.

## Files and modules

Create planned crates/taiyou-render/src/stroke.rs; extend raster/scene and tests/borders_shadows.rs within approved policy. All creation paths in this section are planned; inspect for intervening implementations before editing.

## Technical contract

Implement C5 Core and the explicitly approved R002 legacy rules only. Width/offset coordinate spaces are explicit; shadow fractional offset affects raster phase. Fill, outline and shadow masks remain separate from paint. Coverage subtraction/group rules cannot be invented.

## Expected behavior

Border0 produces no outline; shadow0 coincides spatially but respects pass order; transparent fill does not leave a filled border interior; overlapping glyphs and rotated bordered text match approved fixtures. Zero-axis/anisotropic forms are enabled only if R002 specified them.

## Implementation guidance

R002 output is prerequisite and must be read. Keep fill raster cache identity independent of border width where policy permits.

Read [CONTRACTS](../CONTRACTS.md#c5-geometry-stroke-raster-and-effects). Read [CACHING](../CACHING.md#k3-change-matrix).

## Acceptance criteria

Exact Core analytic tests and approved legacy subset pass, negative/offscreen shadows and support bounds are correct, no extra full-frame allocation per pass.

## Verification

Create border_zero, border_hole, shadow_phase, overlap_pass_order and transform_border integration tests; run focused comparison through T015 and cargo test -p taiyou-render. Commands referring to Cargo/xtask are established by the task that creates that tooling; do not report them run before it exists.

## Forbidden changes

No blur, policy changes, tolerant output acceptance without review or RGBA glyph caches. Ordinary implementation cannot modify protected expected assets, tolerances or support classifications.
