# T009 — Itemization, fallback and shaping

Status: planned. Suggested owner: **Sol 6.1; typography review**. Scope: one focused implementation session unless explicitly bounded as research; split with coordinator approval if unexpected work appears.

## Objective

Shape Core text into owned glyph IDs, cluster maps, metrics and advances.

## Prerequisites

[T008](T008.md), [T007](T007.md). These must meet their acceptance gates before dependent work starts.

## Files and modules

Create planned crates/taiyou-font/src/shape.rs and tests/shaping.rs; add approved shaped types. All creation paths in this section are planned; inspect for intervening implementations before editing.

## Technical contract

Use C4 HarfBuzz design-unit scaling, bidi/script/language itemization and bounded context-aware fallback. Source spans refer to original source bytes through an explicit text-to-source map; do not treat concatenated run offsets as original spans. Keep shaping independent from paint except documented cluster paint policy. Missing clusters produce .notdef plus diagnostics.

## Expected behavior

Combining mark stays with base; Arabic joining and mixed bidi retain cluster provenance; font fallback does not split a supported cluster; color-only boundary preserves ligatures in Core; spacing disables standard ligatures as specified.

## Implementation guidance

Use pinned font fixtures and HarfBuzz's own buffer conventions from selected version. Do not reverse bytes or infer shaping from char-to-glyph lookup.

Read [CONTRACTS](../CONTRACTS.md#c4-font-resolution-shaping-and-layout). Read [TESTING](../TESTING.md#v7-safety-fonts-and-malformed-input).

## Acceptance criteria

Latin/Arabic/Indic/combining/CJK fallback and missing-glyph tests cover glyph sequence and advances; owned results remain valid after context reset.

## Verification

Create fixture manifests with exact font/version and expected glyph/cluster/advance dumps. Run cargo test -p taiyou-font shaping and native sanitizer smoke. Commands referring to Cargo/xtask are established by the task that creates that tooling; do not report them run before it exists.

## Forbidden changes

No platform font discovery, copying libass shaper, layout/wrapping heuristics or legacy feature guesses. Ordinary implementation cannot modify protected expected assets, tolerances or support classifications.

Record any acceptance gate still open; do not mark the task complete when required evidence is missing.
