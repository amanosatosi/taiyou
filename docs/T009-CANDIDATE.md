# T009 shaping candidate

Integration base: `98be6c293ff3b506f5f4f2a03fd0286fd3e2aeb8` (PR 17). The source-map/fixture prerequisite is retained and connected to the parser and evaluator. [ADR-010](decisions/010-shaped-cluster-provenance.md) records owner architectural acceptance and provisional dependent implementation authorization. The separate contract [PR 18](https://github.com/amanosatosi/taiyou/pull/18) and implementation remain unmerged for technical review. This is not a submitted independent GitHub approval. Historical review debt and T005's maintainer configuration/trusted-validation gate remain open.

Parser events publish operation-span sidecars without changing `TextOp` variants. Track publication validates order, UTF-8 extents, intrinsic spans, exact escape bytes and membership in the actual Dialogue Text field. Complete maps cannot omit visible Text bytes or claim escapes inside override blocks. Host-created spanless unit operations remain evaluable but explicitly unmappable for exact shaping. Evaluated text retains original source storage; every decoded span is checked against its owning map. Glyph clusters return all original intervals, never a continuous hull across an override gap.

The native feature provides logical-order Unicode bidi/script itemization, explicit language/base direction, deterministic validated-catalog selection and bounded whole-cluster fallback. Paint-only changes coalesce before shaping. Fallback reshapes selected font ranges with paragraph context and preserves native glyph ordering. Missing clusters produce `.notdef`, font identities, decoded spans and bounded diagnostics. Hard breaks are retained as mapped ranges; line layout and visual line reordering remain later stages. Cluster paint comes from the first logical scalar under C4.

HarfBuzz 14.5.0 uses immutable font bytes and collection indices, per-call buffers, OpenType font functions and design-unit scales. Owned glyph IDs, horizontal/vertical advances and offsets, metrics and direction outlive every native context. FreeType advances are not mixed into shaping. All unsafe calls remain inside `taiyou-font/src/native.rs`; the existing exception allowlist and negative tests remain enforced. RAII cleanup and malformed-face tests exercise failure paths. Native allocation estimates and explicit input/glyph/transient bounds are conservative admission checks, not a process-RSS guarantee or performance claim.

The four pinned inputs and their exact revisions, hashes, licenses and default instances remain in [the proposed font manifest](../build-support/shaping-fonts.proposed.json). Arabic/Indic variable fonts use default instances. The CJK fixture requires explicitly larger test budgets; default production limits are unchanged. Exact optional dependencies are the T002 selections `harfbuzz-sys =0.8.0`, `unicode-bidi =0.3.18` and `unicode-script =0.5.8`; versions, licenses and alternatives are recorded in [DEPENDENCIES](DEPENDENCIES.md). The seven-package DAG is preserved.

An independently authored [C client](../build-support/shaping-reference.c), linked directly to pinned HarfBuzz, supplies observations independently of Taiyou. [Proposed cases](../build-support/shaping-cases.proposed.json) freeze glyph IDs, decoded clusters, integer advances/offsets, units per em and metrics. CI checks frozen observations on each platform before Rust compares scaled results. These are explicitly provisional expectations, not promoted trusted assets or an independently approved baseline. The pinned Latin font has an `ff` ligature but no `fi` ligature: both remain tested, including noncontiguous `ff`/combining clusters and distinct `f{\\c&HFF0000&}i` clusters. Reference/typography review remains an acceptance gate.

Tests cover Latin kerning/ligatures and spacing, Arabic joining and mixed bidi, Devanagari reordering/conjuncts, Japanese CJK, whole-cluster fallback, missing glyphs, collection face identity, scaling, paint selection, UTF-8 and all decoded escapes, BOM/CRLF, lifetime after owner destruction, repeatability, invalid provenance, foreign-map rejection and resource limits. The CLI integration test runs actual parse → evaluate → shape without adding crate dependency edges. Existing tokenizer/evaluator/catalog tests are preserved.

Verification is exclusively on GitHub Actions. The focused lane precedes the existing full workspace/native matrix; it does not replace required gates. The final PR records exact SHA, run/job links and commands. Linux additionally checks exact 1.85.0 MSRV, ABI layouts, the native advisory inventory and ASan/UBSan/leaks with both pinned C libraries instrumented. Rust itself is not sanitizer-instrumented; this is neither fuzzing nor a memory-safety proof.

Explicit boundaries: Core horizontal OpenType shaping only; no OS discovery, LegacyXyV1 guesses, vertical-font shaping, custom feature/variation requests, wrapping, visual line ordering, outlines or rendering. Unicode analysis uses pinned Rust tables, which may lag HarfBuzz's Unicode data; matching all Unicode 18 script/bidi coverage is not claimed. Missing requested families fail explicitly. T010 requires final T009/interface/unsafe/dependency/reference review and integration plus a separate assignment; no T010 work is included.
