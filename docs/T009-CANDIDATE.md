# T009 source-map and fixture prerequisite candidate

Integration base: `1a9d21187fb0359461e03a4e59334b5ed7b90c08`. Session 3 integrated reviewed PRs 16, 13, 14 and 15 in that order through normal GitHub merges under explicit owner direction. Main passed [Fast](https://github.com/amanosatosi/taiyou/actions/runs/39065062702), [Blueprint](https://github.com/amanosatosi/taiyou/actions/runs/39065062679) and the [three-platform native matrix](https://github.com/amanosatosi/taiyou/actions/runs/39065062698), including Linux FreeType ASan/UBSan/leak tests. ChatGPT technical review is not a submitted independent GitHub approval; historical review debt and T005's maintainer configuration/trusted validation remain open.

This bounded T009 increment implements the explicit C4 text-to-source map prerequisite. It does not amend C2, alter the static evaluator or implement glyph shaping. `SourceMappedText::from_pieces` builds decoded text from ordered, nonoverlapping original-source pieces. Literal bytes are copied exactly. Each escape requires its exact two original bytes; a containing event span fails validation. The immutable map retains the original source and returns separate original intervals for decoded UTF-8 ranges, preserving override/paint gaps rather than fabricating a contiguous character span. Soft-break decoding follows C4's WrapStyle rule; this does not enable rendering non-2 wrap modes.

Regression groups cover literal UTF-8/combining boundaries, BOM/CRLF, all three escapes, override gaps, combining text across a paint boundary, coarse/incorrect escape claims, out-of-order/overlapping/invalid extents, invalid decoded boundaries, retained ownership, empty text and injected input/text/transient/operation limits. Pure Rust checks run without the native feature as well as in the existing native matrix. No new integration-test executable changes the existing native sanitizer inventory.

**Remaining bridge gate:** existing C2 unit operations do not carry individual escape spans, and T007 still publishes coarse event provenance for them. This candidate deliberately does not infer those positions or reinterpret an evaluated run as exact. A parser-to-evaluator mapping producer/IR extension needs shared-interface/architect review before automatic pipeline integration. The C4 map interface also needs review before glyph-cluster implementation. Host-created spanless units remain unmappable unless their producer supplies explicit validated pieces. No HarfBuzz glyph/cluster/advance, bidi/fallback or full T009 acceptance claim is made.

Proposed runner-only font inputs cover Latin ligatures/kerning/combining marks, Arabic joining/marks, Devanagari reordering/conjuncts and Japanese CJK. The manifest records exact official commits, Git blob identities, sizes, SHA-256, OFL-1.1 license hashes and version/family/units-per-em/glyph-count/default-axis metadata. Acquisition is size-bounded, rejects traversal/unpinned revisions before networking and verifies all hashes before metadata/nominal-coverage checks. No font binaries are committed or downloaded locally. Arabic and Devanagari fixtures use their recorded default variable-font instances; no variation-axis support is claimed. The 16,467,736-byte CJK fixture exceeds T008's default transient registration estimate: future catalog/shaping tests must explicitly configure a sufficient budget (at least 256 MiB), not weaken the estimate.

These are proposed inputs, not approved expected glyph/cluster/advance dumps. Fixture/validation review and a separately trusted promotion remain required. Existing reference pins, outputs, tolerances and support classifications are unchanged. All executable verification is Actions-only; exact candidate evidence is recorded in PR 17. No performance or process-RSS guarantee is claimed.
